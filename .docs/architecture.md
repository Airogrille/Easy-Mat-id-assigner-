# EasyMatID — архитектура

**Статус:** принята · **Дата:** 07.10.2026 · **Max:** 2025–2027, проверяется на 2027 · **Движок:** Unity URP

Инструмент назначает материалы (Material ID) на полигоны Editable Poly / Edit Poly одним
кликом и готовит меш к экспорту в Unity. Главные требования — **минимум действий** и
**скорость**: известные аналоги (Titus MatID Assistant, Pixamoon MultiSub Organizer) тормозят
и роняют Max.

---

## 1. Модель работы

Один объект за раз. Материал объекта — Multi/Sub-Object, каждый слот — Standard-материал
с цветом из палитры. В Unity каждый слот становится submesh со своим материалом; там
настоящие материалы назначаются по слотам, наши цвета — только разметка.

| Действие | Результат |
|---|---|
| **Add material** | следующий цвет палитры → новый слот → назначен на выделенные полигоны |
| ЛКМ по строке | ID строки → на выделенные полигоны |
| Shift + (Add или ЛКМ) | то же на **весь объект** |
| Без выделенных полигонов и без Shift | ничего не меняется, статус «Select polygons» |
| ПКМ по строке | выделить полигоны этого ID, уровень Polygon включается сам |
| × в строке (виден при наведении) | слот удалён, его полигоны → Blank |
| **Validate** | список проблем для Unity; кнопки Select и Clean у соответствующих пунктов |

**Почему Shift для всего объекта:** случайный клик по объекту с 15 размеченными зонами
перезаписал бы всё; Undo спасает, только если ошибку заметили сразу.

## 2. Материал

- **Тип саб-материала — Standard (Legacy).** Unity из FBX надёжно забирает имя и diffuse
  как Base Color.
- **Blank** — `MT_<Base>_Blank`, нейтральный серый: всё, что ещё не размечено. Первый Add на
  объекте без Multi/Sub создаёт Multi из Blank (ID 1, на все полигоны) и нового цвета.
  Обычный материал на объекте при этом заменяется Blank. Blank вручную не удаляется.
- **Чужой Multi/Sub** на объекте: наши слоты дописываются в него, Blank не создаётся.
- **Общий Multi/Sub** (один материал на нескольких объектах): перед любым изменением
  материала (Add, назначение с автоочисткой, удаление слота, Clean) объект получает
  собственную копию.
- **Validate** сцену не меняет и в Undo не пишется.
- **Имя Multi/Sub** — `<имя объекта>_Multi`; в Unity не попадает.
- **Автоочистка.** После каждого действия, меняющего разметку (Add, назначение, удаление
  слота), **наши** слоты без полигонов удаляются из материала: список всегда равен тому, что
  реально лежит на меше. Чужие пустые слоты
  удаляются только кнопкой **Clean**. «Наш» слот помечен appData в материале — метка
  переживает переименование.
- Удаление слота переводит его полигоны в Blank; нет Blank — он создаётся (ID 1, если
  свободен, иначе следующий).

## 3. Именование

По словарю SpiderRig (`asset-naming.md`): материал — `MT_`, грамматика
`MT_<Base>_<Color>`.

- `<Base>` = имя объекта без `SM_` / `RM_` / `SK_`, всё кроме `[A-Za-z0-9]` → `_`.
  `SM_Factory_Pipe_A` → `MT_Factory_Pipe_A_Red`.
- `<Color>` — название цвета палитры (Red, Yellow, Green…); после полного круга — `Red2`.
  Цвет в имени выбран сознательно: в Unity по имени слота видно, какая это зона.
- Буква-вариант слота отложена: может конфликтовать с буквой варианта меша (`_A_A`).

## 4. Скорость — правила, проверенные замером

Замер на Max 2027 (`.scratch/bench_used_ids.ms`), 16 384 полигона → пересчёт на 100k:

| Способ узнать, какие ID есть на меше | 16k | ≈100k |
|---|---|---|
| Editable Poly, `selectByMaterial` по слоту | 6 мс | ~37 мс |
| Edit Poly, `ButtonOp #SelectByMaterial` по слоту | 3 мс | ~20 мс |
| снимок меша + перебор треугольников | 18 мс | ~115 мс |
| Edit Poly, перебор `GetFaceMaterial` | 689 мс | ~4,3 с |

Отсюда правила:

1. **Работа с полигонами — встроенными операциями Max над наборами (bitarray)**, по одному
   вызову на слот. Ни одного цикла по всем полигонам — ни в Python, ни в MAXScript.
2. **Перебор полигонов через методы Edit Poly запрещён.** Единственное исключение — строка
   «Selected: ID…»: перебор только выделения, с потолком (Editable Poly 20 000, Edit Poly
   1 000 полигонов), сверх потолка — пометка «+…».
3. **Edit Poly хранит ID с нуля**: `materialIDToSet` и `selectByMaterialID` = ID − 1
   (проверено: покраска и замер).
   **Edit Poly из скрипта:** `SetSelection` молча не работает — только метод `Select`;
   модификатор отвечает, только когда он текущий в стеке, поэтому скрипт сам открывает его в
   панели Modify; выбор по ID требует `SetEPolySelLevel #Face` на время операции
   (`.scratch/check_contexts.ms` v1–v5).
4. **Обновление окна читает только материал** (единицы слотов), полигоны не трогает.
5. **Бюджет:** действие ≤ 50 мс на 100k полигонов.
6. Одно действие = один шаг Undo = одна перерисовка вьюпорта. Выделение пользователя,
   изменённое для вычислений, восстанавливается.

## 5. Устойчивость — чего не повторять за аналогами

Titus роняет Max подпиской на **все** события узлов (`NodeEventCallback all:`), которую не
снимает при закрытии окна, и квадратичным перебором полигонов.

- **Узкий список событий:** смена выделения объекта, переход по стеку, Undo/Redo, смена
  материала на объекте, открытие/сброс сцены; изменение выделения полигонов — одна
  `NodeEventCallback` только на `subobjectSelectionChanged`, с задержкой и `mouseUp`.
- Пачка событий схлопывается в одно обновление.
- **Подписки снимаются гарантированно:** закрытие окна, выход из Max, повторный запуск.
  `NodeEventCallback` выключается `.enabled = false` до сброса ссылки.
- Пока скрипт сам меняет выделение для вычислений, свои же события игнорируются.
- Ошибка в обработчике не уходит в Max: перехватывается, пишется в строку статуса.
- Никаких таймеров, опрашивающих сцену.

## 6. Код

Python 3 + PySide6 + pymxs; тяжёлая часть — библиотека MAXScript-функций, загружаемая
один раз.

```text
src/EasyMatID/
  startup/EasyMatID_startup.ms   macroScript, категория "Airo TOOLS"
  easy_mat_id/
    naming.py      имена и палитра; чистый Python, тесты без Max
    emid_core.ms   операции над полигонами и материалом (MAXScript)
    core.py        API для окна; транзакции Undo; не знает про Qt
    ui.py          прикреплённая панель; в сцену не лезет, только через core
tests/test_naming.py
```

**Установка:** junction `src/EasyMatID` → `<userScripts>\EasyMatID`, ссылка на
`startup/EasyMatID_startup.ms` → `<userScripts>\startup\`. Путь к коду — из
`getDir #userScripts`.

## 7. Окно

Прикреплено к правому краю Max, английский интерфейс:
объект и материал · список слотов (цвет, ID, имя, ×) · `Selected: ID …` · Add material /
Validate · результат Validate · строка статуса (с временем действия в мс).

## 8. Validate (только по кнопке)

- материал не Multi/Sub;
- полигоны с ID без слота — **Select**;
- пустые слоты — **Clean**;
- саб-материал не Standard, вложенный Multi/Sub, пустой слот;
- имя не по `^MT_[A-Za-z0-9]+(_[A-Za-z0-9]+)*$`; одно имя на нескольких слотах;
- в сцене другой материал с тем же именем (в Unity склеятся в один).

Blank с полигонами — не ошибка: в Unity у каждого полигона должен быть слот.

## 9. Известное ограничение

Покраска базового Editable Poly под модификатором Edit Poly, который сам уже менял ID этих
полигонов, перекрывается модификатором — так устроен стек Max. Красить там, где идёт работа:
в верхнем Edit Poly.

## 10. Отложено

- Режим библиотеки общих материалов (`MT_<Domain>_<Surface>` + Search and Remap в Unity).
- Буква вместо цвета в имени слота.
- Счётчик полигонов на слот, горячие клавиши, работа с несколькими объектами.
