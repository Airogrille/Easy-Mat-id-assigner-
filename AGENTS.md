# Договор агентов

Проект — скрипты под 3ds Max. Работают два агента: **Claude** анализирует и проверяет,
**Codex** планирует и пишет код. Контекст друг друга они не видят — всё передаётся файлами.
Решение из чата, не записанное в спек, тикет или план, не существует.

## Agent skills

### Issue tracker

Local markdown: issues and specs live as files under `.scratch/<feature>/`. See `.docs/agents/issue-tracker.md`.

### Domain docs

Single-context: `.docs/GLOSSARY.md` + `.docs/adr/`. See `.docs/agents/domain.md`.

## Пайплайн

| Шаг | Кто | Что | Результат |
|---|---|---|---|
| 1 | Claude | `/grill-me` | закрыты все ветки решения |
| 2 | Claude | `/to-spec` в той же сессии | `.scratch/<feature>/spec.md` |
| 3 | Claude | `/to-tickets` | `.scratch/<feature>/issues/NN-<slug>.md` |
| 4 | Codex | план на один тикет | `.scratch/<feature>/plans/NN-<slug>.md` |
| 5 | Claude | проверка плана | вердикт в файле плана |
| 6 | Codex | код строго по утверждённому плану | код + прогон чеклиста |
| 7 | Владелец | проверка в 3ds Max | тикет закрыт |

Шаги 1–3 не разрывать: `/to-spec` синтезирует живой разговор грилла. После шага 3 разрыв
безопасен — всё лежит в файлах. Задача в один файл и пару строк идёт сразу с шага 4.

## План (шаг 4, Codex)

Файл `.scratch/<feature>/plans/NN-<slug>.md`, номер совпадает с тикетом. В плане обязательно:

- какие файлы меняются и что в каждом;
- как это закрывает каждый критерий готовности тикета;
- **чеклист проверки в 3ds Max** — нумерованный, от дешёвых проверок к дорогим, у каждого
  пункта названо, как выглядит провал.

## Проверка плана (шаг 5, Claude)

Фильтр, а не «посмотри». Проверить:

1. План закрывает все критерии тикета и ничего сверх тикета и спека.
2. Не противоречит `.docs/` и ADR.
3. Риски MAXScript учтены: undo-блоки на изменения сцены, поведение на пустом выделении
   и на сотнях объектов, выделение и режим пользователя восстанавливаются после скрипта.
4. Чеклист проверки есть и проверяем руками в Max.

Вердикт дописывается в конец файла плана:

```markdown
## Вердикт

**Вердикт:** утверждён — YYYY-MM-DD
```

или `**Вердикт:** правки — YYYY-MM-DD` и нумерованный список правок. Правки → назад к шагу 4.
**Код без вердикта «утверждён» не начинается.**

## Код (шаг 6, Codex)

По плану, без импровизации. Если план не работает — остановиться, записать в план раздел
`## Отклонения` с причиной и вернуть на шаг 5. Молча отступать от плана нельзя.

## Проверка в 3ds Max (шаг 7)

Пока MCP 3ds Max не подключён — чеклист из плана проходит владелец руками. Когда подключён:
Codex гоняет скрипт через MCP во время кода, Claude повторяет чеклист независимо после.
Одновременно в одну сцену два агента не пишут.

Компиляция и чистый Listener — слабое свидетельство. Поведение подтверждается прогоном.

## Закрытие тикета

Закрывает владелец фразой после проверки в Max, не агент по своей инициативе. Тикет закрыт,
когда в нём стоят `**Status:** done` и `**Дата:** YYYY-MM-DD`.

## Команды

Блоки команд для владельца — под **PowerShell**, не bash. Кто запустил команду сам —
присылает вывод хотя бы одной строкой.

## Модель и эффорт

Самая умная модель — на анализ, самая дешёвая — на исполнение.

| Шаг | Модель | Эффорт |
|---|---|---|
| грилл, спек, тикеты, проверка плана, отладка непонятного | Claude Opus | высокий |
| план, код | Codex | обычный |
| механика: переименования, форматирование | любая дешёвая | низкий |

Claude напоминает переключиться на Opus с высоким эффортом при входе в шаги 1–3 и 5.
